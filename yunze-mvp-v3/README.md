# 云泽璞舍 · 洱海密语

面向入境游客的白族文化**多语种解码 + 沉浸式数字叙事**系统原型。
H5 网页端与微信小程序端**同源共用**一份内容与算法，**零构建、零依赖、离线可跑**。

> 对应 2026 年第十四届全国大学生数字媒体科技作品及创意竞赛国际专项赛
> 作品形式：数字应用与交互系统 · 鼓励方向：智慧文旅与跨文化体验

## 1. ★ 怎么让别人「直接扫开」——这是最关键的一节

结论先给：**让别人扫码打开的，必须是 H5 链接；小程序在 5 天内做不到。**

### 1.1 为什么小程序扫不开（务必先看，避免白做）

| 你想用的方式 | 现实 | 能否让陌生人扫开 |
|---|---|---|
| 开发者工具里「预览」生成的二维码 | 有效期 25 分钟，且只有开发者本人能打开 | ❌ |
| 「体验版」二维码 | **只有开发者 + 体验成员白名单**能打开，评委不在名单里 | ❌ |
| 「开发版」二维码 | 同上 | ❌ |
| **正式发布后的小程序码 / 二维码** | 任何人都能扫开 | ✅ 但要走完全部流程 |

走完流程要多久：

```
注册小程序账号（邮箱 + 主体信息）      →  当天
小程序备案（2024 年起强制）             →  管局审核 1—20 个工作日
提交代码审核                            →  1—7 天
发布 + 生成小程序码                      →  当天
────────────────────────────────────────────────────
合计：最快约 2 周，通常 3—4 周
```

今天是 11 月 1 日，11 月 6 日截止。**全新注册小程序不可能赶上。**

> **唯一的例外**：如果你们（或指导老师、学院）手上已有**一个已完成备案、曾发布过的小程序账号**，
> 那么「上传代码 → 提交审核 → 发布」通常 1—3 天就能完成。这种情况是可行的，
> 改一下 `project.config.json` 里的 `appid` 即可。**今晚就要确认这件事。**

所以正确的提交策略是：

- **作品本体 = H5 在线版**（评委扫码即开）＋ 小程序工程包（源码 + 运行说明 + 体验版录屏）
- 这完全符合《指南》五（二）1：「提交完整项目 Demo、可运行程序、工程文件……并提供必要的运行环境与操作说明」

### 1.2 H5 部署：四条路线，按可行性排序

| 路线 | 得到什么 | 备案 | 国内可访问 | 耗时 | 建议 |
|---|---|---|---|---|---|
| **腾讯云 CloudBase 静态托管** | `https://xxx.tcloudbaseapp.com/` | **默认域名免备案** | 稳定 | 10 分钟 | ✅ 主链接 |
| **Netlify Drop**（app.netlify.com/drop） | `https://xxx.netlify.app/` | 无需 | 一般，偶有波动 | 1 分钟（拖拽即传） | ✅ 备用链接 |
| GitHub Pages | `https://用户名.github.io/仓库名/` | 无需 | 经常打不开 | 5 分钟 | ✅ 已配好 Actions，push 即发布；国内访问不稳，作备份 |
| 阿里云 OSS 静态网站 | 默认 endpoint 域名 | — | 默认域名会强制下载，不能直接访问网页 | — | ❌ 别用 |
| 自建服务器 + **已备案**域名 | 自己的域名 | 需备案 | 稳定 | 备案 1—2 周 | 来不及 |

> 自定义域名需要 ICP 备案；**平台分配的默认域名不需要**。所以 5 天内请务必用默认域名。

**CloudBase 具体步骤**

1. 打开 <https://console.cloud.tencent.com/tcb>，微信扫码登录
2. 新建环境（选按量计费，有免费额度）
3. 左侧「静态网站托管」→ 开通
4. 把 `h5/` 目录里的**全部文件**上传到根目录
   （`index.html`、`app.js`、`style.css`、`data/` 整个目录都要传）
5. 复制控制台给的「默认域名」，形如 `https://xxx-125xxxx.tcloudbaseapp.com`
6. 浏览器直接打开这个域名，应看到首页

**易错点**：只传了 `index.html` 而漏掉 `data/` 目录 → 打开是白屏。
`data/` 里是全部内容与算法，必须一起传。

### 1.3 生成二维码

三种方式，任选其一：

**① 本项目自带的离线生成器（推荐）**

双击 `tools/qr.html` → 填入真实网址 → 点「生成」→ 点「下载 PNG」。
完全离线（已内置 MIT 协议的 qrcode 库），不联网也能用。

**② 草料二维码**：<https://cli.im> ，粘贴网址，10 秒出图。

**③ CloudBase 控制台**：静态托管页面本身会显示访问二维码。

### 1.4 验证是否真的能扫开（必做）

1. 用**另一台手机**（不要用部署时登录的那台）
2. 打开**微信 → 右上角 + → 扫一扫**
3. 能打开首页、能点进「白族扎染」、能切换 English → 就算通过
4. 再试一次「用手机自带相机扫」——有些场合评委会用系统相机

> 微信内置浏览器对**未备案域名**可能弹「非微信官方网页，继续访问？」。
> 平台默认域名一般不会拦。如果被拦了，换 Netlify 备用链接。

### 1.5 现场二维码（线索码）：把「找线索」变成真的

`tools/qr.html` 的第二个标签页「批量线索码」：

1. 填站点根地址（不带 `#`），例如 `https://xxx.tcloudbaseapp.com/`
2. 点「生成 6 张线索码」
3. 点「打印 / 存 PDF」，打印后贴到院子里的对应位置：

| 线索码 | 贴在 | 绑定的知识卡 |
|---|---|---|
| YH-01 | 照壁前 | 三坊一照壁 |
| YH-02 | 晾布架下 | 白族扎染 |
| YH-03 | 茶案旁 | 三道茶 |
| YH-04 | 灶头 | 甲马（纸马） |
| YH-05 | 门楼内侧 | 白族民居彩绘 |
| YH-06 | 院心火塘 | 白族火把节 |

玩家扫码 → 直接落到 `#/s/play?clue=YH-03` → 自动解锁该线索并弹出知识卡。
**「找线索」这个动作本身就成了学习文化的过程**——这是答辩时最值得讲的一段，也是评审视频里最有画面感的一段。

无法打印 / 没网络时，页面里有「模拟扫码（演示用）」按钮，效果等价。

### 1.6 其他坑

| 现象 | 原因 | 处理 |
|---|---|---|
| 白屏 | `data/` 目录没上传 | 上传整个 `h5/` 内容 |
| 扫码后空白但链接能开 | 二维码内容带了多余空格 | 重新生成 |
| 双击打开后切换页面正常但刷新丢失进度 | `file://` 下部分浏览器禁用 localStorage | 用 `node tools/serve.mjs` 或部署后访问 |
| 手机底部被裁 | iOS 地址栏高度 | 已用 `100dvh` 兜底，仍异常就刷新一次 |
| 语音朗读没反应 | 非 https 或浏览器不支持 | 部署为 https 后正常；小程序端本就不提供朗读（平台无系统 TTS） |

### 1.7 用 GitHub 部署与留痕（推荐现在就走这条）

这个目录**已经是一个 git 仓库**了：分支 `main`，首个提交 `2f07d36`，48 个文件全部已提交。
还带了一个 GitHub Actions 工作流 `.github/workflows/deploy-pages.yml`——每次 push 到 `main`，它会自动：

1. 校验 `shared/` 与两端 `data/` 是否一致（防止改了源码忘了同步）
2. 跑完 131 项断言 + 312 项静态检查（**测试不过就不发布**）
3. 通过后把 `h5/` 发布到 GitHub Pages

**第一步：推到你的 GitHub**

1. 在 GitHub 新建一个空仓库（建议叫 `yunze-mvp`），**不要**勾选 README / .gitignore / License
2. 在本目录执行：

```bash
git remote add origin https://github.com/<你的用户名>/yunze-mvp.git
git push -u origin main
```

> 需要先在电脑上登录过 GitHub（`git config --global user.name/user.email` 已经是你的账号，
> push 时按提示走浏览器授权或用 Personal Access Token 即可）。

**第二步：打开 Pages**

仓库 → Settings → Pages → Build and deployment → **Source 选 `GitHub Actions`**。
再进 Actions 标签看一眼，等绿色对勾出现（约 1 分钟）。

**第三步：拿到地址**

```
https://<你的用户名>.github.io/yunze-mvp/
```

把这个地址贴进 `tools/qr.html` → 生成二维码 → 用微信扫，确认能开。

> **注意仓库必须是 public**（私有仓库要 GitHub Pro 才能开 Pages）。

**第四步（重要）：准备一个国内可用的备用链接**

GitHub Pages 在国内访问**经常打不开或很慢**。评委若在国内，主链接请用
CloudBase 默认域名或 Netlify（见 1.2），GitHub Pages 作为**备用链接**。
说明文档里同时给出两个地址，反而显得你考虑周全。

**仓库本身也是「过程可核验」的证据**

《指南》四（二）3 要求「过程、测试和关键结论可核验」。从今天起**按天提交**：

```bash
git add -A
git commit -m "day2: 补齐 30 条知识库条目与双语术语表"
git push
```

提交历史 + Actions 里每次的测试通过记录，比任何文字说明都硬。
评审视频里也可以录一下这个页面——「我们的每一步都有据可查」这句话就有了画面。

## 2. 小程序怎么跑起来

1. 下载安装 [微信开发者工具](https://developers.weixin.qq.com/miniprogram/dev/devtools/download.html)（稳定版）
2. 「导入项目」→ 目录选 `miniprogram/` → AppID 选「测试号」
   （`project.config.json` 里已写 `touristappid`，游客模式可直接编译）
3. 编译后底部出现四个 tab：**解码 / 密语 / 看板 / 主持**

**游客模式的限制**：能本地模拟运行，但**不能真机预览、不能上传、不能发布**。
要真机看到，把 `project.config.json` 的 `appid` 换成你们自己的小程序 AppID 即可。

**真机调试注意**：`wx.scanCode` 在部分模拟器上不可用，代码里已做兜底——
扫码失败时自动退化为「推送下一条未解锁线索」，不会卡住演示。

## 3. 做了什么（对照评审要点）

| 评审维度 | 本原型提供的证据 |
|---|---|
| 主题与需求 | 首页把问题写成一句话：「看得见风景，读不懂文化」；8 个文化对象即 8 个真实痛点入口 |
| 创新性 | ①知识条目与空间线索绑定，找线索＝学文化；②回答逐条溯源、低置信度拒答；③多语种由术语表约束而非自由机翻 |
| 技术实现 | 检索打分 + 阈值拒答 + 引用编号；剧本状态机（幕/线索/分支/结局）；埋点与聚合；七语界面 + 内容回退链 本语→en→zh |
| 成果完成度 | 双端可运行、可离线、有单测与冒烟测试、代码可交付 |
| 应用价值 | 看板输出语种分布、对象热度、剧情漏斗；剧本与空间解耦，换内容即可搬到下一个村落 |
| 展示答辩 | 主持台可现场控场；`?clue=` 深链支持现场二维码；七语一键切换（含阿拉伯语 RTL） |

八个模块：

- **解码**（M1）选择或提问一个文化对象 → 匹配度、解读、要点、出处、体验建议；无关问题**拒绝编造**，只给候选
- **密语**（M2）5 个身份、3 幕、6 条线索、3 个结局；线索按码/扫码解锁，解锁时弹出对应知识卡
- **看板**（M3）开场场次、线索解锁、结局数、平均评分、语种分布、对象热度、剧情漏斗
- **主持**（DM）查看当前幕与身份、逐条推送线索、重置、事件日志
- **民宿 · 住**（M4）按策划书 3.3.2「分层房型」设 6 类房型（银发康养观海 / 风格庭院双床 / 轻奢独栋 / 家庭亲子 / 胶囊榻榻米青年铺 / 宠物友好阁楼），价格覆盖 300–500 元主力区间与 400+ 高端；含面积、床型、窗景、价格、设施与体验文案；支持选房并持久化（键名 `yz_room`，H5 与小程序同源）；入住须知对齐策划书 9.2 运营管理规范（监控告知、消防、核销与 30 天退款）
- **旅游 · 大理攻略**（M5）按策划书 4.1 三条官方线路 + 1.3/5.1 两类主题共 5 条路线（环洱海文化体验线 / 苍山生态探索线 / 古城历史穿越线 / 短时高效游·免签中转 / 民宿周边·沉浸体验游），按「第 N 天」分站呈现行程、贴士、美食与注意事项；附 6 个必看风景
- **加入我们**（M6）策划书 2.2「一宿带一村」的合作招募：7 个合作方向（非遗传承人 / IP 联名 / 村集体分红 / 农庄直供 / 研学机构 / 本地商家 / 校园人才）、5 个招募岗位（对齐 6.2 团队构成）、4 步合作流程、「保底 + 分红」轻资产模式说明；意向表单提交后落 `join_apply` 埋点
- **文创商城**（M7）策划书 4.1.2 / 4.1.3 的线上文创商城：12 件商品分 5 类（扎染布艺 / 木雕陶艺 / 民族服饰 / 纸本文创 / 联名系列），含分类筛选、购物袋（键名 `yz_cart`，双端同源、持久化）、数量增减与合计、模拟预约下单（落 `shop_order` 埋点，说明正式版将接入微信支付与二维码核销）

> 民宿与旅游的内容层统一放在 `shared/showcase.js`，「加入我们 + 文创商城」放在 `shared/growth.js`（与知识库、剧本一样由 `sync.mjs` 同步到双端）。
> 首页「住 / 旅游」两张入口卡带实景照片，「文创 / 加入我们」用品牌色渐变卡；房型与路线配程序生成的 SVG 插画（data URI）保证离线可显示，缺失时优雅降级。
> H5 端路由：`#/h` 民宿 · `#/t` 旅游 · `#/join` 加入我们 · `#/shop` 文创商城（首页四张入口卡进入，底栏 tab 保持 6 个不拥挤）；小程序端为非 tab 子页，首页入口卡 `navigateTo` 进入。

## 6. 设计取舍（写进说明文档的「关键技术」）

1. **不做大模型实时问答**。回答全部来自本地知识库的检索与拼装，因此：弱网可用、零 API 成本、绝不可能编造文化解释。
   大模型接入点被隔离在 `engine.js` 的 `llmHint()`，接入时必须保留引用校验，否则会破坏「可溯源」这一产品承诺。
2. **不引入向量库**。8—60 条知识完全可放进上下文或直接关键词打分，反而更可控。
   说明文档里写明「条目超过 500 条后引入向量检索」，这本身就是一条工程判断。
3. **阈值拒答而非硬答**。`LOW_THRESHOLD = 26`，低于阈值一律返回候选条目。
   文化类应用宁可说「我不知道」，也不能猜。
4. **多语种靠术语表，不靠机器自由翻译**。核心概念（本主、三道茶、照壁、甲马）固定译法，
   由国际成员审校——这同时也是「国际成员真实参与」的证据。
5. **剧本与空间解耦**。线索在 `story.js` 里是纯数据（码、位置名、知识卡 id、奖励文本），
   换一套数据就能复制到下一个民宿，不需要改代码。
6. **双端同源代码，不做跨端框架**。原生小程序 + 原生 H5 更稳，5 天内不能赌工具链。
   共享层只放数据与纯函数，两端各自的渲染代码不到 500 行。
7. **双端导航差异（刻意）**。H5 底部 tabBar 直接放 6 项（解码/民宿/旅游/密语/看板/主持）；
   小程序 tabBar 上限 5 个，故民宿/旅游设为非 tab 子页，从首页两张实景入口卡 `navigateTo` 进入。
   内容与逻辑完全一致，仅入口形态不同。
8. **图片策略（零依赖、可离线）**。房型/路线配程序生成的 SVG 插画（data URI，离线可见）；
   首页入口卡、民宿头图、旅游头图使用 4 张实拍照片（`assets/` 双端各一份），`<image>`/`img` 缺失时仅显示渐变或色调色块，不报错、不空白。
   **正式申报前须替换为团队真实勘景照片与房型实拍。**
9. **七语界面分层回退（面向免签客群）**。界面层 `i18n.js` 七语完整（zh/en/ja/es/ar/hi/ko，180 键 × 7）；
   内容层（知识条目、剧本、房型、路线、商品）目前 zh/en/ja，其余语言按「本语 → en → zh」回退并显示提示，
   翻译到位后只需往内容对象里加键，无需改代码。阿拉伯语自动切换 RTL（H5 设 `html[dir=rtl]`，
   flex 行与文本对齐随写作方向镜像），语音朗读映射 es-ES / ar-SA / hi-IN / ko-KR。

## 7. 已知边界

- 小程序端**没有语音朗读**（微信无系统 TTS 接口）；H5 端用 Web Speech API 实现。
- 日文内容目前覆盖界面与知识条目摘要，长正文与剧本回退到英文并显示提示。
  这是刻意设计：与其交一份机器翻译的日文，不如如实标注翻译进度。
- 主持台为**单机模拟**（同一台设备的 localStorage）。真实部署应改为云数据库同步的第二台设备。
  这一点在 `dm` 页面底部已明确标注，答辩时不要含糊。
- 未做预订/支付/会员——它们与评审要点无关，且会拖垮 5 天排期。
